## 用例说明

- **类型**：`功能测试 (正向)`（正常业务流主路径）/ `异常测试`（错误与校验
  场景的前端提示与 UI 状态）/ `交互测试`（弹窗、确认、多步操作交互流）
- **Given**（前置条件 + 测试数据）：所需账号状态 / 页面状态 / 具体输入值，
  用实际数值而非占位符（如"金额 0"而非"非法金额"）
- **When**（操作步骤）：按用户操作顺序，每步一个动作短语（登录 / 进入 /
  输入 / 点击），用 `→` 连接；弹窗、确认等交互操作单独成步。**每步 MUST
  指向具体组件**（用下方"组件"字段中的组件名，如 `在 [转出账号输入框] 填入
  A`），不能只写业务动作不写对象
- **Then**（预期结果）：具体可见 UI 行为——精确提示文案（含标点）、元素
  状态（按钮置灰 / 弹窗出现 / 输入框报错）、数据变化（余额减少 / 显示流水
  号）；文案以后端实际返回为准（与契约错误码 / 校验逻辑一致）。**每条 Then
  MUST 指明断言对象（组件名或文案）与断言方向（出现 / 消失）**
- **组件（Playwright 定位依据，MUST）**：每条用例列出关键 UI 组件及定位
  依据，供 Playwright 选择器直接采用。**定位依据优先级**：`data-testid`
  （testid）→ `placeholder`（占位文案）→ 按钮/链接可见文本 → 表单标签
  （label/aria-label）。**实际 selector 以当前前端源码为准**——前端有
  `data-testid` 时必须优先使用；案例集中的定义是依据性描述，供 e2e AI 在
  源码中精确确认
- **断言超时**：出现断言带显式 timeout（默认 `5000ms`）；"出现 / 消失"成对
  断言（如提示出现 + loading 消失），禁只断言一半
- **禁止**含糊表述：如"验证转账功能正常"、"检查页面提示"（无具体文案）、
  "输入错误账号"（未指明错误类型）、"点击某按钮"（未指明按钮文案/定位）。
  e2e 测试 AI 无法自行推断模糊内容。
